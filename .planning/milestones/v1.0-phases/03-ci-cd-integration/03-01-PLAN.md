<task type="auto">
  <name>Task 1: Add flutter variant to build.yml with three-tier chain</name>
  <files>.github/workflows/build.yml</files>
  <action>
Modify `.github/workflows/build.yml` to add the flutter variant:

1. Add a new matrix entry to `strategy.matrix.include` in the `variants` job:
   ```yaml
   - name: trixie-vnc-flutter-rust-nvm-uv-claude
     scope: flutter
     needs_vnc: true
     build_contexts: trixie-vnc-nvm-uv-claude:latest=docker-image://localhost:5000/trixie-vnc-nvm-uv-claude:latest
   ```
   Also add `build_contexts` to ALL existing matrix entries so the main build step can use `matrix.build_contexts` uniformly:
   ```yaml
   - name: trixie-bun-nvm-uv-claude
     scope: bun
     build_contexts: devcontainer-base:latest=docker-image://localhost:5000/devcontainer-base:latest
   - name: trixie-php-nvm-uv-claude
     scope: php
     build_contexts: devcontainer-base:latest=docker-image://localhost:5000/devcontainer-base:latest
   - name: trixie-rust-nvm-uv-claude
     scope: rust
     build_contexts: devcontainer-base:latest=docker-image://localhost:5000/devcontainer-base:latest
   - name: trixie-vnc-nvm-uv-claude
     scope: vnc
     build_contexts: devcontainer-base:latest=docker-image://localhost:5000/devcontainer-base:latest
   ```

2. Add a conditional VNC rebuild step AFTER the "Rebuild base from cache" step and BEFORE the "Extract metadata" step:
   ```yaml
   - name: Rebuild VNC from cache and push to local registry
     if: matrix.needs_vnc
     uses: docker/build-push-action@v6
     with:
       context: .
       file: trixie-vnc-nvm-uv-claude/Dockerfile
       push: true
       tags: localhost:5000/trixie-vnc-nvm-uv-claude:latest
       build-contexts: devcontainer-base:latest=docker-image://localhost:5000/devcontainer-base:latest
       cache-from: type=gha,scope=vnc
   ```
   IMPORTANT: This step pushes to the LOCAL registry (localhost:5000), NOT to GHCR. The `cache-from` scope must be `vnc` (the VNC variant's existing cache scope). Do NOT add `cache-to` here -- the VNC variant's own matrix job already writes its cache.

3. Update the existing "Build and push" step to use `matrix.build_contexts` instead of the hardcoded `build-contexts` value:
   ```yaml
   build-contexts: ${{ matrix.build_contexts }}
   ```
   This replaces the existing hardcoded line:
   ```yaml
   build-contexts: devcontainer-base:latest=docker-image://localhost:5000/devcontainer-base:latest
   ```

The `matrix.build_contexts` approach is cleaner than a ternary expression. For existing variants, `build_contexts` maps to the base image on localhost. For the flutter variant, it maps to the VNC image on localhost (since the flutter Dockerfile's FROM references `trixie-vnc-nvm-uv-claude:latest`, not `devcontainer-base:latest`).
