**Step 1: Build the Docker image**

Build the Flutter devcontainer image using the project's standard build pattern. The image extends `trixie-vnc-nvm-uv-claude:latest`, so the base and VNC parent must be available. Build with:

```bash
docker build -f trixie-vnc-flutter-rust-nvm-uv-claude/Dockerfile -t flutter-devcontainer .
```

If the build fails because the parent image `trixie-vnc-nvm-uv-claude:latest` is not available locally, build the chain first:

```bash
# Build base image
docker build -f base/Dockerfile -t devcontainer-base:latest .

# Build VNC variant (parent of Flutter variant)
docker build -f trixie-vnc-nvm-uv-claude/Dockerfile -t trixie-vnc-nvm-uv-claude:latest --build-context devcontainer-base:latest=docker-image://devcontainer-base:latest .

# Build Flutter variant
docker build -f trixie-vnc-flutter-rust-nvm-uv-claude/Dockerfile -t flutter-devcontainer --build-context trixie-vnc-nvm-uv-claude:latest=docker-image://trixie-vnc-nvm-uv-claude:latest .
```

Note: The build takes a long time (potentially 30-60+ minutes) due to Flutter SDK download, Android SDK components, and Rust compilation. Use `--progress=plain` to see full output. Consider using build cache if available from a previous Phase 1 build.

**Step 2: Start the container**

Run the container interactively with enough memory and VNC port exposed:

```bash
docker run -d --name flutter-validate \
    --memory 6g \
    -p 5900:5900 \
    -p 8080:8080 \
    flutter-devcontainer \
    sleep infinity
```

Use `-d` (detached) + `sleep infinity` so the container stays running while we exec commands into it.

**Step 3: Copy and execute validation script**

```bash
docker cp scripts/validate-flutter-runtime.sh flutter-validate:/tmp/validate-flutter-runtime.sh
docker exec -it flutter-validate bash -l /tmp/validate-flutter-runtime.sh 2>&1 | tee validation-output.log
```

Use `bash -l` (login shell) to ensure .bashrc is sourced and all PATH entries are available.

IMPORTANT: The emulator boot step takes 2-5 minutes with SwiftShader. The script has a 10-minute timeout. Do NOT interrupt or set a short Bash timeout. Use at least `timeout: 600000` (10 minutes) on the docker exec command.

**Step 4: Capture evidence**

After the script completes, capture key evidence:
```bash
# Capture the validation log
echo "--- Validation Output ---"
cat validation-output.log

# Verify the CLAUDE.md inside the container has ADB docs
docker exec flutter-validate cat /home/dev/.claude/CLAUDE.md
```

The script should end with `ALL_CHECKS_PASSED` if everything succeeded.

**Step 5: Leave container running for VNC verification**

Do NOT stop the container yet. The user needs to connect via VNC for the checkpoint task. Print:
```
Container 'flutter-validate' is running with VNC on port 5900.
Connect with a VNC client to localhost:5900 to verify emulator and Android Studio visually.
```

**If validation fails:** Check the specific section that failed. Common issues:
- "command not found" for nvm/uv: Shell not sourcing profiles -- use `bash -l`
- Emulator boot timeout: Increase memory (`--memory 8g`), check emulator logs with `docker exec flutter-validate cat /tmp/emulator-*.log` if the script captures them
- Flutter web build fails: Check CHROME_EXECUTABLE and DISPLAY are set
- Android Studio fails to start: Check DISPLAY is :99 and Xvfb is running

**Cleanup (after checkpoint):**
```bash
docker stop flutter-validate && docker rm flutter-validate
rm -f validation-output.log
```
